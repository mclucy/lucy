# Lucy Alpha 与 Beta 遥测规格

本规格记录维护者已确认的遥测行为，供后续客户端与服务端实现使用。本文不表示功能已经实现。MUST／必须表示强制要求，SHOULD／应表示可说明理由的建议，MAY／可以表示可选行为。

## 1. 目的与范围

为指定 Alpha 测试参与者收集最小运行环境、命令执行结果、失败诊断日志和 agent 自主报告，用于开发与排障。Beta 沿用本规格的默认开启策略；稳定版默认策略不在范围内。

本次交付仅为规格，不修改生产代码、不创建远程仓库、不添加真实 submodule、不部署服务、不采集实际数据。后续实现覆盖 Lucy CLI、一次性上传子进程、Rust 服务端、D1 存储与清理、令牌管理、软件内告知和用户政策文档。

不包含：账号系统、公开注册、管理网页、公开数据查询、后台常驻服务、重试队列、完整会话收集、Minecraft 服务端日志采集、地理画像、统计仪表盘，以及 #183 中独立的命令冒烟与发包工作。

## 2. 定义

| 术语 | 含义 |
| --- | --- |
| 普通事件 | 一次业务命令结束后的结构化记录；失败时可附本次进程诊断日志 |
| Agent 报告 | Agent 主动通过隐藏命令提交的受约束 Markdown 报告 |
| 参与者标识符 | 当前 OS 用户范围随机生成的假名标识，不从硬件、账号或路径推导 |
| 上传令牌 | 维护者给参与者独立分发的可撤销鉴权凭据，不是统计标识 |
| 配置开启 | 显式配置或构建默认值选择开启，即使尚未配置令牌 |
| 可上传 | 配置开启、令牌存在、标识符与安全交接所需本地状态可用 |
| 交接文件 | 一次性上传进程消费的已脱敏数据，不是可重放的持久队列 |
| 服务端类型 | Lucy 已知的实际服务器产品身份，例如 Fabric、Paper；不含本地目录名称 |
| KiB | 1,024 字节；256 KiB 为 262,144 字节 |

“匿名”不得用于承诺不可识别：参与者标识符可关联记录，服务端保存 IP，令牌分发关系也可能识别参与者。

## 3. 要求、约束与生命周期

### 3.1 开关、身份与用户级配置

- **CFG-001**：官方 Alpha、Beta 构建默认开启；开发构建默认关闭。显式持久化开关优先于构建默认值。不得从稳定版未定义的默认策略推导自动开启。
- **CFG-002**：配置作用域为当前 OS 用户，跨服务器目录共用。配置目录采用 OS 用户配置目录下的 Lucy 专属位置，不写入服务器 manifest、lock 或当前工作目录。
- **CFG-003**：配置包含开关、原始上传令牌、随机参与者标识符，以及实现取消和防止旧任务复活所需的本地状态。不得将用户名、主机名、硬件标识作为替代身份。
- **CFG-004**：首次具备上传条件时生成密码学随机参与者标识符；开启期间跨命令复用。`off` 删除标识符，再次开启生成新的标识符，但保留令牌。令牌关联关系不因此消失，不得宣称重新开启后不可关联。
- **CFG-005**：默认开启但没有令牌时不得上传，不注入 agent 上报指令；应告知配置方式。普通业务命令不得因缺少遥测配置失败。
- **CFG-006**：用户级配置和交接文件必须限制为当前 OS 用户访问；Unix 使用私有目录与文件权限，Windows 必须满足等效 ACL 隔离，不得仅依赖 Unix 文件模式位。
- **CFG-007**：配置不可读、损坏、无法建立私有权限或无法安全判断开关时，遥测必须停止，不以默认开启覆盖异常。业务命令保持原结果；显式管理命令报告配置错误。

### 3.2 普通事件与环境选择

- **EVT-001**：每次业务命令结束最多产生一个普通事件，覆盖成功、失败和可观察到的取消。已恢复并继续执行的中间错误不单独产生事件。普通命令参数解析失败也属于失败。
- **EVT-002**：帮助、版本查询、shell 补全、内置文档和所有遥测管理／上传命令不产生普通事件。内部上传进程不产生事件，不触发 agent 报告。
- **EVT-003**：命令使用规范化路径，别名映射到正式命令，如 `lucy i` 记录为 `lucy install`。无法识别的命令使用固定的未知类别，不发送包含用户输入的未知命令文本。
- **EVT-004**：仅收集第 4 节定义的字段。不得增加原始参数、耗时、设备名、硬件序列号、环境变量全集、包清单或目录清单等未确认字段。
- **EVT-005**：服务端类型和 Minecraft 版本只来自本次命令实际操作环境。成功改变环境时使用成功后的值；失败时使用操作前已知的值。未知或没有目标环境时留空，不猜测，不为遥测额外联网或发起目录扫描。
- **EVT-006**：调用者使用既有 agent 检测结果；可确认人工交互时记为人类，无法确定时记为未知。未检测到 agent 不足以证明是人类。多个检测条件同时命中时采用确定性选择，不收集环境变量原值。
- **EVT-007**：正常处理的失败应完成事件准备；无法捕获的崩溃、强制杀进程、断电等不保证产生记录。不得为保证送达引入常驻进程或下一次运行补发。

### 3.3 错误、日志与隐私过滤

- **PRV-001**：失败事件可以包含脱敏后的错误说明和诊断日志。错误说明、解析错误和日志适用相同隐私规则；不得借错误字段泄漏原始参数。成功与取消事件不附自动诊断日志；取消若被明确作为失败处理，则按失败规则记录。
- **PRV-002**：日志来源仅为本次 Lucy 进程自身产生的诊断记录，包含 DEBUG 诊断，不取决于终端镜像级别。不读取整个既有日志文件，不包含其他 Lucy 并发进程或历史调用的记录。
- **PRV-003**：不得主动读取 Minecraft 服务端日志、其他程序日志、完整 agent 会话、完整工具记录、凭据文件或无关文件。服务端类型等已获准字段可以复用业务操作已知信息。
- **PRV-004**：客户端在写交接文件或发请求前过滤已识别的凭据、URL 查询参数、用户名和本地绝对路径。服务端在持久化前再次过滤。替换标记应保留诊断结构，不伪装为原始值。
- **PRV-005**：过滤为尽力而为，不承诺识别全部敏感信息。原令牌、Authorization 头、未过滤正文不得进入服务端诊断日志、错误响应或管理输出。
- **PRV-006**：失败日志经过过滤后最多保留末尾 262,144 个 UTF-8 字节；保留有效字符边界，独立记录是否截断。过滤必须保留足够上下文识别跨片段敏感值，不得先任意截断再漏掉凭据标签。截断标志不占日志正文限额。
- **PRV-007**：本规格采用日志截断，不采用 D1 日志分块、不新增对象存储。日志与 agent 正文均须满足各自字节限制；请求元数据还需有独立的有限结构与字段长度校验，不接受无界任意 JSON。

### 3.4 一次性异步上传与关闭竞态

- **UPL-001**：普通事件由脱离主命令生命周期的一次性进程上传。主命令只承担有限的本地采集、脱敏、交接和启动开销，不等待网络结果。仅启动 goroutine 然后退出不满足要求。
- **UPL-002**：后台上传总时限为从上传进程启动开始 10 秒；一次尝试后退出，不重试、不退避、不跟随重定向、不补发、不成为常驻服务。令牌只发送给受信任的 HTTPS 接收端点。
- **UPL-003**：交接文件只含已脱敏的一份数据及必要的本地任务状态，不包含令牌。令牌不得放在子进程参数或环境变量中；上传进程从私有用户配置读取。
- **UPL-004**：上传进程先读取并删除交接文件，再发起请求。若不能安全消费并移除交接文件则放弃上传。交接文件不是后续运行可发送的队列；异常遗留文件只清理、不重放。
- **UPL-005**：临时状态保存在 Lucy 用户级私有位置；并发任务各自独立。清理不得删除其他运行中任务的有效数据或无关用户文件。
- **UPL-006**：启动失败、权限错误、脱敏失败、网络错误、超时、HTTP 错误或服务端拒绝均不得改变普通命令的退出码、结果、回滚行为或 JSON 文档。可记录本地遥测失败，但不得再生成遥测或 agent 报告。
- **UPL-007**：`off` 必须先持久化关闭状态，禁止新任务，作废旧任务的上传资格，清理交接文件，并尽力取消所有当前用户的遥测上传，包括显式 agent 报告。旧任务不能在稍后重新开启时恢复发送，不能把旧记录改写成新的参与者标识符。
- **UPL-008**：每次实际发请求前重新检查资格和开关；令牌不能从旧交接状态继续使用。关闭与发送必须有明确的本地并发协调，不能只依赖一次早期检查。
- **UPL-009**：`off` 不保证撤回关闭前已发出的字节或已接收的数据。已上传记录按保留期处理。持久化关闭失败必须让 `off` 返回错误，不能声称成功关闭。

### 3.5 Agent 自主报告

- **AGT-001**：隐藏的 `lucy telemetry agent-report` 从标准输入接收非空 UTF-8 Markdown，支持可选但鼓励填写的 `--model`、`--harness`。不自动读取报告文件、工作目录或会话存储；shell 输入重定向由调用者决定。
- **AGT-002**：正文覆盖操作目标、失败步骤、预期与实际结果和必要诊断片段。禁止完整会话、完整工具记录、无关文件和已知敏感信息。正文最多 262,144 字节；超出明确拒绝，不自动截断。输入侧和服务端均执行限制。
- **AGT-003**：报告包含与普通事件相同的客户端环境和参与者字段，但作为独立记录，不要求普通事件 ID，不自动为报告命令生成普通事件。`--model` 如实记录，未知留空；`--harness` 优先使用显式值，否则可复用检测结果。
- **AGT-004**：报告命令同步等待服务端确认，网络上传阶段总超时 10 秒，不重试。仅在服务端确认持久化成功后返回上传成功；失败返回非零，并明确送达状态可能未知。调用者提供 stdin 的等待不是网络上传超时。
- **AGT-005**：仅在可上传且检测到 agent 时注入上报指引：Lucy 业务命令失败后，完成必要诊断并提交一次报告。不得因上传失败再写报告或自动重试，不要求每次成功操作写报告。
- **AGT-006**：开关关闭、缺令牌、无安全本地状态时，报告命令在本地拒绝，不访问网络；应在读取可能阻塞的 stdin 前完成资格检查，发送前再次检查。

### 3.6 令牌、服务端与数据保留

- **SEC-001**：维护者通过受控脚本或 Cloudflare 管理通道创建、分发和撤销每位参与者的独立高熵令牌。不开发公开注册、账号系统或管理后台。服务端只保存不可逆摘要，客户端保存原令牌。
- **SEC-002**：令牌仅用于鉴权和撤销，不替代随机参与者标识符作为统计身份；事件表和报告表不增加令牌分组统计字段。政策说明维护者保留的分发关系及 IP 仍可能关联参与者。
- **SEC-003**：服务端先鉴权，再处理有界正文；拒绝缺失、无效和已撤销令牌。校验字段白名单、类型、UTF-8 和正文大小，不将未知字段无条件落库。不得用客户端内置共享密钥冒充参与者鉴权。
- **SEC-004**：主动保存实际连接 IP，仅用于排障和防滥用，不用于生成参与者标识符、跨用户身份重建或地理画像。采用受信任 Cloudflare 边缘提供的连接信息，不信任请求正文或任意客户端提供的转发头。
- **SEC-005**：事件、错误、日志、报告和 IP 仅维护者通过受控管理通道访问，无公开读取 API。接收端不得提供跨用户数据查询。令牌管理记录与遥测内容分开存储。
- **RET-001**：以服务端接收时间作为数据寿命依据，保留完整接收时间而不依赖客户端时钟。事件、错误、日志、报告、IP 在接收满 30 天后不允许查询，最迟满 31 天从活动数据库删除。
- **RET-002**：每日定时清理过期记录，查询同时执行 30 天过滤，不能仅依靠清理任务让数据不可见。维护者的日常读取工具必须经过该过滤；底层运维权限不得作为日常读取过期内容的绕过路径。
- **RET-003**：D1 恢复历史、平台访问／安全日志可能保留额外副本。部署时核实套餐、日志配置及保留窗口并披露，不承诺第 30 天消除所有备份字节。数据库恢复后先删除过期数据，再恢复读取和上传服务。
- **RET-004**：令牌摘要及撤销状态属于鉴权配置，不套用事件的 30 天自动过期规则；不得因此保留过期遥测内容。

### 3.7 告知与输出契约

- **UX-001**：参与者加入前口头告知，同时提供软件内告知及公开政策页面。政策说明字段、失败日志、agent 报告、默认开启、自动无确认上传、过滤局限、IP、令牌可关联性、关闭方式、保留与恢复历史、不出售及不用作广告。
- **UX-002**：人类输出模式下，配置开启时每次实际业务命令显示简短启用提示及 `lucy telemetry off`；缺令牌时显示尚不能上传与配置方法。每次实际上传前显示明确提示，不弹确认。提示走 stderr，不污染正常 stdout。
- **UX-003**：异步交接、启动成功或“正在尝试上传”不等于“已上传”。后台进程不得在主命令退出后向其终端追加成功／失败输出；普通异步上传的最终结果记录到本地诊断。
- **UX-004**：JSON／紧凑 JSON 模式不插入文字、额外 JSON 字段或额外 JSON 文档。启用与上传提示改记诊断日志；agent 指引告知自动上传。政策明确机器模式不逐次显示终端提示这一例外。
- **UX-005**：报告命令如启用机器输出，仍按既有单一结果／错误文档契约输出。所有提示遵循既有无颜色、无交互和无样式规则；`--yes` 不是开启遥测的替代操作。

## 4. 接口与数据契约

本节给出供两端共同实现的接口命名；域名、submodule URL 与固定提交是实际部署输入，不在本次写 spec 时捏造。

### 4.1 CLI

| 命令 | 行为 |
| --- | --- |
| `lucy telemetry on --token-stdin` | 从 stdin 读取并私密保存令牌及开启状态；已存在令牌时替换。不得回显令牌 |
| `lucy telemetry on` | 有已保存令牌时开启；缺令牌时非零退出并说明 `--token-stdin` 用法，不弹交互提示 |
| `lucy telemetry off` | 执行 UPL-007 至 UPL-009；幂等，不上传关闭事件，不删除已保存令牌 |
| `lucy telemetry agent-report [--model MODEL] [--harness HARNESS]` | 隐藏命令；按 AGT-001 至 AGT-006 上传报告 |

`on` 是本地配置操作，不以远程连通性确认令牌有效；无效或撤销的令牌会被接收端拒绝。令牌输入必须有界，允许移除输入重定向产生的末尾换行，拒绝空值或不合法令牌。不得新增接受明文令牌参数的入口。

使用示例：

```sh
lucy telemetry on --token-stdin < token.txt
lucy telemetry agent-report --model MODEL --harness HARNESS < report.md
lucy telemetry off
```

示例文件由参与者自行安全管理；Lucy 不创建含令牌的示例文件。内部一次性上传入口属于私有实现，不出现在帮助中，不成为对用户承诺的额外命令。

### 4.2 请求

采用 HTTPS JSON：普通事件 `POST /events`，报告 `POST /agent-reports`。令牌使用 `Authorization: Bearer …`，不放在 URL 或正文；禁用重定向。构建／部署提供受信任的接收端地址，不接受由服务器目录文件替换端点。

两类请求共用下列字段，除此不隐式扩充采集范围：

| 字段 | 类型 | 语义 |
| --- | --- | --- |
| `participant_id` | string | 随机参与者标识符 |
| `lucy_version` | string | 当前构建版本；未知不伪造 |
| `lucy_commit` | string 或 null | 构建提交，使用已有构建身份；未知为 null |
| `os_name` | string | OS 名称 |
| `os_version` | string 或 null | 可通过本地系统信息获得的 OS 版本；失败留空 |
| `architecture` | string | 当前 Lucy 构建／进程所用 CPU 架构，不探测硬件指纹 |
| `server_type` | string 或 null | EVT-005 定义的服务端类型 |
| `minecraft_version` | string 或 null | EVT-005 定义的游戏版本 |
| `caller` | object | `kind` 为 `human`、`agent` 或 `unknown`；`harness` 为检测到的名称或 null |

普通事件增加：

| 字段 | 类型 | 语义 |
| --- | --- | --- |
| `command` | string | 规范化命令路径或固定未知类别，无参数 |
| `outcome` | string | `success`、`failure` 或 `cancelled` |
| `error` | string 或 null | 脱敏后的失败说明；未知可空 |
| `log` | string 或 null | 本次进程脱敏诊断日志，仅失败时可有 |
| `log_truncated` | boolean | 日志是否丢弃前缀；无日志时为 false |

Agent 报告增加：

| 字段 | 类型 | 语义 |
| --- | --- | --- |
| `body` | string | 非空 Markdown，最多 262,144 UTF-8 字节 |
| `model` | string 或 null | 调用者提供的模型信息，不猜测精确模型 |
| `harness` | string 或 null | 显式参数优先，否则检测结果；可空 |

### 4.3 响应与存储

| HTTP 状态 | 含义 | 客户端处理 |
| --- | --- | --- |
| `201` | 校验、过滤和持久化全部成功 | 唯一的上传成功确认；响应仅含服务端记录 ID |
| `400` | 格式、字段或内容不合法 | 本次失败，不重试 |
| `401` | 令牌缺失、无效或已撤销 | 本次失败，不重试；不回显令牌 |
| `413` | 请求或正文超过限制 | 本次失败，不分块补传 |
| `429` | 接收端拒绝或平台限流 | 本次失败，不重试 |
| `5xx`、其他状态或网络错误 | 未确认成功；可能已经落库 | 本次失败，不重试，不声称肯定未送达 |

D1 分开存普通事件、报告、令牌摘要／撤销状态；记录 ID、接收时间和可信连接 IP 由服务端生成。事件和报告无需关联外键。内容以参数绑定写入，不把日志或 Markdown 拼接为 SQL。普通参与者只拥有写入权限，不能凭上传令牌读取记录。

服务端必须在 D1 成功写入后才返回 `201`，不能先确认再异步尝试保存。元数据长度及整个请求的安全上限由实现按照已限定字段计算并校验，必须能容纳各自完整 256 KiB 正文及 JSON 转义开销；不得误把请求总大小限制等同于正文限额。

## 5. 验收标准

| ID | Given / When / Then |
| --- | --- |
| AC-001 | 给定无显式开关，运行官方 Alpha／Beta 或开发构建，则默认分别为开启／关闭；显式配置覆盖构建默认 |
| AC-002 | 给定默认开启但缺令牌，运行业务命令，则无遥测请求、无上报指引，业务结果不变，提示安全配置方式 |
| AC-003 | 给定已保存令牌，执行 `on`、业务命令、`off`、再次 `on`，则跨目录复用身份，关闭清除身份，再次开启身份不同但令牌保留 |
| AC-004 | 给定配置损坏或无法确保私有权限，运行业务命令，则遥测停止且业务结果不变；显式管理命令报告失败 |
| AC-005 | 给定业务命令成功／失败及别名调用，则各最多收到一条规范化事件；成功事件无日志，失败含脱敏诊断；原始参数不出现在结构化字段 |
| AC-006 | 给定帮助、版本、文档、补全、遥测命令或内部上传进程，则无普通事件；未知命令输入不作为命令文本上传 |
| AC-007 | 给定操作改变环境或中途失败，则分别使用成功后环境／操作前已知环境；无目标或未知时留空，遥测不触发额外环境探测 |
| AC-008 | 给定历史日志、并发命令与本次日志混在同一文件，触发失败，则上传仅包含本次进程记录；DEBUG 是否镜像到终端不影响采集 |
| AC-009 | 给定含已知测试凭据、查询参数、用户名和绝对路径的错误及跨片段日志，则交接文件和落库数据均不含这些原值；超限日志保留有效 UTF-8 尾部并标记截断 |
| AC-010 | 给定端点连接挂起、拒绝、超时或返回错误，运行业务命令，则命令不等网络完成且结果不变，上传进程在 10 秒上限后终止，无重试或下次补发 |
| AC-011 | 给定交接文件遗留或上传子进程异常退出，则后续仅清理、不上传；令牌不在交接文件、进程参数或环境变量中 |
| AC-012 | 给定并发任务已交接但尚未发出、正在传输及随后重新开启，执行 `off`，则不产生新上传，尽力取消在途上传，旧任务不复活；关闭前已到达的数据不承诺撤回 |
| AC-013 | 给定有效 stdin 报告，服务端持久化返回 `201` 后命令成功；超时或错误则非零且不递归报告；关闭或缺令牌时不读取阻塞 stdin、不联网 |
| AC-014 | 给定 262,144 字节合法正文和超出一字节正文，前者可接收，后者客户端及服务端均拒绝、不截断；测试多字节 UTF-8 边界 |
| AC-015 | 给定可上传的已检测 agent，业务失败后指引只要求诊断后报告一次；成功、关闭、缺令牌及上报自身失败不触发新报告 |
| AC-016 | 给定无效／撤销令牌、伪造 IP 正文字段或转发头、未知字段，则接收端按鉴权／校验拒绝或采用可信边缘 IP；无公开读取能力，存储与诊断均无原令牌 |
| AC-017 | 给定接收时间满 30 天记录，则维护者正常查询不可见；每日清理确保最迟 31 天活动数据删除；恢复旧快照后先清理再开放 |
| AC-018 | 给定人类／JSON 模式，分别观察 stderr 提示／既有单文档机器输出；交接不显示已上传，子进程不在命令结束后污染终端 |
| AC-019 | 给定接收端 D1 写入失败，则不返回成功确认；超时但落库成功也不自动重试，客户端不伪称肯定未送达 |
| AC-020 | 给定 Linux、macOS、Windows 及 amd64／arm64 可用运行环境，验证用户隔离、子进程脱离、取消与私有权限；不得因平台使用量猜测省略实现 |

## 6. 验证与自动化策略

本次规格交付只验证文档结构、接口示例、交叉引用与已确认决策的一致性，不声称已完成运行时验收。

后续实现以真实 CLI 与本地 Worker／D1 的端到端 smoke 为主，使用隔离 OS 用户配置与私有临时目录、虚假测试令牌及合成敏感值；不得向生产遥测端点发测试数据。覆盖第 5 节所有场景，尤其是进程退出后的送达、关闭／重新开启竞态、JSON 流、失败日志隔离与 UTF-8 字节边界。

- 客户端沿用 Taskfile 和既有 e2e 习惯；服务端在 submodule 中独立提供构建、迁移、受控令牌管理、清理任务与本地验收入口。
- 使用可挂起／失败的接收端观察主命令返回与后台时限，不能用 mock 的“已启动”断言代替实际进程与网络结果。
- 只为隐私边界、并发状态、大小边界、保留时间和错误处理等真实不确定行为保留回归测试；不测试文案副本、源代码字符串或简单转发。
- 平台不可用时明确记录未验证的平台；不能把交叉编译成功等同于进程和 ACL 行为已验证。
- 验证完成后删除临时报告、令牌、测试数据库和子进程状态。不得把真实参与者信息写入 fixture。

## 7. 决策理由与现有约束

- 一次性独立进程满足主命令不等待网络；临时文件是单次交接，不将“不重试”演变为持久队列。
- 原始日志可能含超过结构化字段范围的信息，因此失败日志和自由文本必须单独披露，客户端及服务端分别过滤，且不能宣称完全匿名。
- 256 KiB 限额取代完整日志分块，控制传输与 D1 存储成本；普通日志取尾，agent 正文则超限拒绝以保留语义。
- 上传令牌保护指定参与者的 Alpha 接收端；高熵随机身份支持故障关联，但与 IP、令牌关系一起带来可识别风险。
- 当前 `log/logger_init.go` 的诊断目标始终记录 DEBUG；`log/logger_io.go` 以追加方式打开共享日志文件。因此实现不能直接读取该文件尾部充当本次进程日志，也不能直接复用其目录权限作为私有交接权限。
- 当前 `.goreleaser.yaml` 向 `cmd.version` 和 `cmd.commit` 注入身份，并构建 Linux、macOS、Windows 的可用目标；遥测复用身份，不创建第二套版本来源。采集规则不等于新增发行矩阵要求。
- 现有 agent 检测与内置文档能力应复用；遥测指引、输出模式和环境观察由既有边界衔接，不扩展 catalog 或 workspace 的职责。

## 8. 外部集成与部署依赖

| 依赖 | 要求 |
| --- | --- |
| Rust／WASM Worker | 独立 Git 仓库，通过父仓库 submodule 固定提交；拥有自身构建与部署配置，不要求 Go 构建时编译服务端 |

| Cloudflare D1 | 参数化存储、时间索引、鉴权摘要、受控查询和过期删除；单行与数据库容量须符合套餐限制 |

| 参与者接入 | 口头说明、公开政策、令牌私密分发及 `on --token-stdin` 操作说明 |
| 用户政策页 | 在实现交付时新增公开遥测页面，并可通过 `lucy docs` 获取；内容只解释用户可见行为与风险 |

实际部署前维护者需提供服务端仓库 URL、submodule 固定提交、接收域名、Cloudflare 账户／套餐和 D1 绑定，并核实恢复历史及平台日志保留配置。这些是部署参数，不是允许客户端自行发现的端点，不阻塞本次规格交付。规范不捏造已存在的域名解析、凭据或部署结果。

## 9. 示例与边界条件

- `lucy install` 失败：生成一个失败事件、附本次脱敏日志；agent 可在诊断后另交一份自主报告，两者不要求关联。
- `lucy docs view …`：无普通事件。关闭遥测不会禁用文档能力。
- Agent 未被检测到：调用者记未知；不读取环境全集来猜 harness。
- DNS 失败、接收端返回 `429`：普通命令结果不变，后台退出，无后续补发。
- `off` 与重新 `on` 紧接发生：旧事件作废，即使新开关为开启也不恢复；新命令使用新随机标识符。
- 报告刚刚被服务端接收但客户端超时：本次显示未确认成功，不重试；不能承诺删除该记录或保证不存在。
- 服务端接收的内容经二次过滤后为空：不以虚构正文填补；非法／无有效报告内容时返回校验错误。
- 令牌与 Markdown 都从 stdin 输入，但属于不同命令，不复用输入格式，也不把令牌当成报告正文。

## 10. 完成与发布检查

后续实现只有在 AC-001 至 AC-020 被逐项验证或明确列出环境阻碍、两端接口一致、用户政策可访问、管理及过期清理真实可用时，才能声称遥测功能已完成。不可将仅编译通过、空 Worker、未部署数据库或只写成功路径当作完成。

发布前必须验证受控接入端点、令牌创建与撤销、关闭后无新上传、JSON 输出不受污染、隐私合成样本过滤、服务端拒绝未授权读取，以及活动数据和恢复历史的实际披露。遥测之外的 Alpha 命令冒烟与发布闸门仍归 #183，不由本文替代。
