---
title: "Recover and revert files"
description: "Restore accepted contents or an earlier revision"
---

## Recover accepted contents

If an edit breaks your server, restore the current accepted revision:

```bash
lucy file recover config/example.json
```

Lucy keeps a local copy of the contents it replaces. To recover every tracked file with an accepted revision, use `lucy file recover --all`; files tracked without a hash are skipped.

If the local copy is unavailable, Lucy can use the file's configured recovery URL. The download must match the accepted contents; otherwise recovery fails without changing the destination.

## Return to an earlier revision

To restore the preceding accepted revision and make it current, run:

```bash
lucy file revert config/example.json
```

Repeated reverts continue backward through the accepted history. Inspect that history to choose a particular revision:

```bash
lucy file history config/example.json
lucy file revert config/example.json --revision 4
```

You can also pass a recorded SHA-256 hash as the second argument to `revert`, instead of `--revision`.

## Recover on another machine

Local revisions stay in the workspace. A recorded hash does not include the file itself. Before installing on another machine, either place the accepted file at its declared path or make it available at its configured `recover_url`. Lucy does not yet provide an export command.

To fetch and accept newer contents from a recovery URL instead of restoring the existing revision, use `lucy file update --from-source <path>`.
