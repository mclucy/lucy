---
title: "lucy store"
description: "Inspect and reclaim the global artifact store"
---

Lucy keeps verified installed artifacts in a per-user content-addressed store. The store is separate from the network cache: it survives cache expiration and `lucy cache clear`, and it is shared by every server on the machine. An artifact is stored by its SHA-256 digest, once, regardless of how many servers or filenames use it.

```bash
lucy store list
lucy store ls
lucy store gc
```

`list` and `ls` are the same command.

## lucy store list

Lists every object in the store with its digest and size. Human output summarizes the object count and total size; `--json` prints one array of objects with `digest` and `size`.

```bash
lucy store list
lucy store list --json
```

The listing does not modify stored objects.

## lucy store gc

Removes objects that no registered server's lock references. A lock retains every artifact it pins, including disabled packages, because enabling one later must not require the bytes to be fetched again. Objects used only by a transient resolution or a failed installation are reclaimed.

Garbage collection is deliberately conservative:

- It reads the lockfile of every [registered server](/commands/install#known-servers) while holding that workspace's writer lock.
- It refuses to delete anything when another lucy operation holds an artifact-store acquisition lease, when a registry entry is missing, unreadable, or invalid, when an installation is interrupted, when a lock cannot be read, when a lock names an artifact without a usable SHA-256 digest, or when another lucy operation owns a registered workspace. Run `lucy install` in an interrupted workspace to recover it before collecting. If a server directory was deleted, remove its stale entry with [`lucy server forget`](/commands/install#lucy-server-forget); reconnect a temporarily unavailable drive instead.
- It holds the operation gate from the lease check through the last deletion, then takes the workspace writer locks and the registry lock before computing references; the store lock is acquired only for the sweep. An operation that holds an artifact-store lease therefore cannot publish an object into the middle of a sweep. This guarantee applies only to operations that hold a lease.

Run `lucy install` once in a server directory after restoring or moving it so its entry and lock are current before collecting. To reclaim artifacts for a server whose directory was deleted, first remove its stale entry with `lucy server forget <path>`, then run `lucy store gc`. Collection refuses to run while any other lucy operation holds the artifact-store operation lease, and it holds the lease gate from its lease check through the last deletion. A command that starts on a registered workspace meanwhile can report that another lucy operation owns it, so retry after collection.

```bash
lucy store gc
lucy store gc --json
```

`--json` prints `removed` and `bytes`.

## Location

The store lives in lucy's per-user data directory:

|Platform|Directory|
|---|---|
|macOS|`~/Library/Application Support/lucy/artifacts`|
|Linux|`$XDG_DATA_HOME/lucy/artifacts` (usually `~/.local/share/lucy/artifacts`)|
|Windows|`%LOCALAPPDATA%\lucy\artifacts`|

Lucy creates the directory when it first needs the store. No workspace-local downloads directory is used.

Installation also consults the network cache when the store misses. See [Artifact store and download cache](/commands/install#artifact-store-and-download-cache).

`--json` and the shared output flags are described in [Global Flags](/commands/global-flags).
