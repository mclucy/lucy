---
title: "lucy init"
description: "Adopt an existing server directory"
---

`lucy init` turns an existing server directory into a lucy workspace. It writes `lucy.yaml`, which records the server you want, and resolves `lucy-lock.yaml`, which records the exact files that satisfy it. Later commands read the manifest as the source of truth.

The generated manifest names the server and registers it in your user's [known-server list](/commands/install#known-servers). The name defaults to the current directory's base name, or to the existing name when `--force` replaces a manifest. Pass `--name` to store a different one.

```bash
cd path/to/server
lucy init
```

Init detects the installed server software, Minecraft version, and supported mods and plugins, and checks the versions against the official release lists. It may download server files into `.lucy`, but it does not install or start the server, accept the EULA, or migrate a world. To create a new server instead, use [`lucy create`](/commands/create).

## Choose a server

If the directory holds more than one server, lucy asks which one to adopt. Select one directly with `--entry-point <jar-or-script>`; without a terminal, lucy fails and prints the command to use. In a workspace that already has a manifest, `--force --entry-point` switches to a different installed server.

If no server is detected, init fails.

## Existing manifest

`lucy init` never overwrites `lucy.yaml` without `--force`. Replacing a manifest discards the package declarations it contained.

## What gets recorded

Init records the server name, software, Minecraft version, server directory, and the installed mods and plugins it recognizes. Packages it recognizes are managed from then on: later installs can replace or remove them. A package without a matching release stays unmanaged and produces a warning, so you can decide whether to add it yourself.

The name is metadata: changing it does not alter the server definition, the installed files, or the lock's manifest match. Init registers the workspace so the artifact store can retain the lock's artifacts; a registration failure fails the command. Registration warns when another registered server already uses the name, and `--server` cannot select an ambiguous name until one manifest is renamed.

The generated `lucy.yaml` explains each field inline. Pass `--no-comments` to omit those comments and the schema header. Init also creates `.lucy/config.yaml` with every setting commented out, unless that file already exists; see [`lucy config`](/commands/config).

## MCDReforged

Pass `--mcdr-version` to record MCDReforged as the server wrapper when lucy cannot detect the version you want. Installation can then use your global MCDReforged or an isolated environment.

## Versions

The Minecraft version and the server version are validated together. A combination the software never published is rejected rather than producing a server that cannot boot, and the manifest stores concrete versions so installs stay reproducible.

## Flags

<ParamField query="--name" type="string">
  Server name stored as the top-level `name` in `lucy.yaml` and used in the known-server list. Defaults to the current directory's base name, or to the existing name when `--force` replaces a manifest. The name is trimmed and must be non-empty and printable.
</ParamField>

<ParamField query="--mcdr-version" type="string">
  Record MCDReforged at this version as the server wrapper.
</ParamField>

<ParamField query="--entry-point" type="path">
  Select an installed launcher or jar when several servers share the directory. The path may be relative to the current directory or absolute.
</ParamField>

<ParamField query="--force, -f" type="boolean" default="false">
  Replace an existing `lucy.yaml`.
</ParamField>

<ParamField query="--no-comments" type="boolean" default="false">
  Omit generated comments and examples from `lucy.yaml` and any new `.lucy/config.yaml`.
</ParamField>
