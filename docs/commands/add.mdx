---
title: "lucy add"
description: "Add packages to the manifest and install them"
---

`lucy add` records a new package in `lucy.yaml`, resolves it against the lock, and installs the result. The manifest change and the lock update are one transaction: if resolution fails, `lucy.yaml` is left exactly as it was.

```bash
lucy add modrinth:lithium
lucy add curseforge:238222
lucy add modrinth:fabric-api@0.100.8
lucy add modrinth:fabric-api modrinth:lithium
lucy add mcdr:synced --ecosystem mcdr
```

## Arguments

<ParamField path="package" type="string" required>
  One or more package references.

  References include the package source, such as `modrinth:lithium`, `curseforge:238222`, or `mcdr:synced`. An `@` suffix pins a version — `modrinth:fabric-api@0.100.8`. Without `@`, the recorded version rule is `any`.

  A bare name such as `lithium` works as a shortcut. `lucy` first looks for a unique match among the package names the current lock already records; if nothing matches, it falls back to Modrinth, or to the MCDR catalogue when adding an MCDR plugin. A name matching more than one locked package is an error asking for a `modrinth:project`-style reference rather than a guess.

  Lucy does not rename the IDs inside a mod or plugin. The manifest stores the `modrinth:`, `curseforge:`, or `mcdr:` reference; the ID stays whatever the server loads.
</ParamField>

Without a pin, the recorded version rule is `any`: Lucy prefers release builds and may fall back to a prerelease when no release satisfies. `stable` requires a release build with no prerelease fallback, and `beta` also accepts prereleases. To hold a version, add it with `@` or edit the package's `selector` afterwards. Adding a package does not float the rest — existing pins are pins, and the new package resolves against them.

The mod or plugin type is inferred from the declared server when `--ecosystem` is omitted: Fabric, Forge, and NeoForge servers select their matching type, Paper and Purpur select `paper`, and MCDR selects `mcdr`. Pass `--ecosystem` when the manifest does not make the target clear.

## Output

`lucy add` reports progress on stderr while it resolves and installs, then lists what changed. Added packages are marked `+`, and a dependency pulled in by the new package is attributed to it. When the package is already installed at the same version, no package line is printed; only the document update is announced.

```text
✓ Resolved 3 packages in 0.8s
✓ Installed 3 files in 0.2s

  + fabric-api    0.119.4+1.21.4
  + ferrite-core  7.1.3-fabric
  + lithium       mc1.21.4-0.15.3-fabric

Updated lucy.yaml and lucy-lock.yaml
```

When the version you asked for does not exist, the error lists the builds that do exist and suggests a concrete `@` pin. When every build is rejected for a shared reason, the error states that reason once with the number of builds it covers. A failed `add` writes nothing, so the manifest and lock stay as they were.

`--json` prints the result as a machine-readable object on stdout, including the package changes, file counts, and fetch counts. `--no-interactive` (and `--no-style`) replace the animated display with append-only lines for CI logs.

## Flags

<ParamField query="--ecosystem" type="string">
  Target mod or plugin type for the request: `fabric`, `forge`, `neoforge`, `bukkit`, `paper`, or `mcdr`.
</ParamField>

<ParamField query="--with-optional" type="boolean" default="false">
  Also pull in optional dependencies that would otherwise be skipped. Anything selected this way is written back into `lucy.yaml` as an explicit package, so it is included when the server is reconstructed later — not just for this run.
</ParamField>

<ParamField query="--locked" type="boolean" default="false">
  Do not resolve new versions; fail when the lock cannot satisfy the request.
</ParamField>

<ParamField query="--offline" type="boolean" default="false">
  Disallow network access. Adding a package changes the manifest, so a package that needs re-resolution fails under `--offline`; the flag is useful only when the lock already pins the result.
</ParamField>

See also [Global Flags](/commands/global-flags) and [`lucy remove`](/commands/remove).
