---
title: "lucy install"
description: "Install a server from its manifest and lock file"
---

`lucy install` makes the current directory match `lucy.yaml` and `lucy-lock.yaml`. Run it after changing the manifest, on a fresh machine, or in CI to reproduce a server exactly.

```bash
lucy install
```

If `lucy.yaml` changed, lucy resolves a new lock before installing. Versions you pinned stay pinned, so adding one package does not upgrade the others. With only `lucy-lock.yaml` present, lucy rebuilds from the lock alone and registers the workspace as a lock-only entry; commit both files to keep the named-server option.

For CI, `lucy install --locked` fails when the lock is missing or out of date instead of resolving new versions.

## What install changes

Install places the files the lock lists. It removes files it installed earlier that the lock no longer lists; files you placed in `mods/` or `plugins/` yourself are left alone.

Installation stops when a destination file already exists. Pass `--overwrite` to replace it, including jars from a manual setup. It also refuses a server whose mod dependencies cannot be satisfied; `--accept-broken` installs the declared packages anyway.

`--with-optional` adds optional dependencies and writes them into `lucy.yaml`, so they remain part of the server on later installs. It resolves again even when the lock is current.

Files tracked with [`lucy file`](/commands/file) are not overwritten. If an immutable tracked file differs from its accepted contents, lucy warns and leaves your copy in place.

## Offline

`lucy install --offline` uses only files already present in the global artifact store or the shared network cache. It replays a current lock in a new workspace when every required artifact is available and the required local prerequisites are present, such as a Java runtime for a step that runs Java. It fails when the manifest needs a new resolution, an artifact is unavailable, or a prerequisite is missing. A file whose contents do not match the lock counts as missing, even if it exists.

### Artifact store and download cache

Lucy keeps one verified copy of each artifact in a per-user artifact store shared by every server. The lock pins the objects a server needs, so clearing the network cache does not remove installed artifacts. `lucy store list` shows the stored objects; `lucy store gc` reclaims objects that no registered server's lock references.

The network cache remains a separate, expiring copy of upstream responses and downloads. `lucy cache clear` empties it without touching the artifact store or the files in a server directory. Run an online install before relying on `--offline` when the artifact is not already in the store.

## MCDReforged

By default, install runs the `mcdreforged` command on your `PATH`, which needs Python 3.8 or newer. Pass `--mcdr-venv` to create an isolated environment under the server directory instead. The isolated environment needs one online install before it can be used offline; a global MCDReforged installation does not.

## Java

Java version mismatches are warnings, not install errors. If a step needs a runtime and none is installed, the command stops and suggests `--java`. That flag installs a suitable runtime without changing your default Java. If you selected a runtime with `java.home` in [`lucy config`](/commands/config), `--java` installs nothing and your choice is used. Under `--offline`, `--java` fails instead of downloading.

`--add-java-repository` lets `--java` add the Java vendor's package repository to your system package manager. Under `--no-interactive`, methods that need a password are skipped.

## Known servers

Lucy keeps a list of servers for your user account in your user data directory. The list is shared by every shell and project and records locations only. A server appears after [`lucy create`](/commands/create), [`lucy init`](/commands/init), or `lucy install` registers it; [`lucy deinit`](/commands/deinit) removes the entry.

Every install registers its workspace before it acquires artifacts. A manifest may omit `name`; the server remains registered but cannot be selected by name. A lock-only installation is registered as a `lock-only` entry. Registration failure fails the installation because `lucy store gc` cannot retain artifacts for a server it cannot find. Registration warns when another server already uses the name.

### lucy server list

```bash
lucy server list
lucy server ls
```

Lists each registered server's name, state, and path. `list` and `ls` are the same command.

|State|Meaning|
|---|---|
|`available`|The path exists and its manifest can be read and validated.|
|`lock-only`|The path exists and holds a valid `lucy-lock.yaml`, but no manifest. Collection retains its lock's artifacts; `--server` cannot select it.|
|`missing`|The path no longer exists, for example because a drive is disconnected.|
|`unreadable`|The path or manifest exists, but lucy cannot inspect it, usually because of permissions or an I/O error.|
|`invalid`|The path exists but does not contain a valid lucy manifest, or the registry entry itself cannot be interpreted.|

The listing checks each registered target without changing it. A missing server stays in the list; lucy never removes an entry because a target is unavailable. Reconnect the drive and list again to see it as `available`. Only `lucy deinit` removes an entry.

An empty name is shown as `-`. An unnamed server cannot be selected with `--server`. Lock-only, missing, unreadable, and invalid entries also cannot be selected.

### lucy server rename

```bash
lucy server rename <server> <name>
```

Renames a registered server. `<server>` must match exactly one available name; when several servers share it, the command fails, lists the matching paths, and changes nothing.

`<name>` becomes the top-level `name` in that server's `lucy.yaml`. It is trimmed and must be non-empty and printable. Renaming to a name another server already uses is allowed with a warning; selecting that name then fails until you change one manifest's `name` directly. Renaming to the current name changes nothing and still refreshes the registration.

Only the name changes. The installed server, packages, worlds, configuration, and directory stay in place. The name is not part of what the lock compares, so renaming does not make `lucy-lock.yaml` stale.

### Machine-readable output

`lucy server list --json` prints one array. Each entry has `name`, `path`, and `state`, plus `problem` when there is a problem.

```json
[
  {
    "name": "survival",
    "path": "/srv/minecraft/survival",
    "state": "available"
  }
]
```

`lucy server rename --json` prints the previous name, the new `name`, and the server `path`, plus `warnings` from registration, for example when the new name is already in use.

## Flags

<ParamField query="--locked" type="boolean" default="false">
  Do not resolve new versions; fail when the lock is missing or cannot satisfy the manifest.
</ParamField>

<ParamField query="--offline" type="boolean" default="false">
  Disallow network access. Missing files must already be available in the cache.
</ParamField>

<ParamField query="--with-optional" type="boolean" default="false">
  Also install optional dependencies and record them in `lucy.yaml` as explicit packages. Cannot be combined with `--locked`.
</ParamField>

<ParamField query="--accept-broken" type="boolean" default="false">
  Install the declared packages even when a mod dependency is missing or a version falls outside its required range. Each problem is reported as a warning.
</ParamField>

<ParamField query="--overwrite" type="boolean" default="false">
  Replace files already present at the destinations the lock selects. Other files are left alone.
</ParamField>

<ParamField query="--force, -f" type="boolean" default="false">
  Combine `--accept-broken` and `--overwrite`.
</ParamField>

<ParamField query="--java" type="boolean" default="false">
  Install the Java runtime the server asks for when no installed runtime meets it.
</ParamField>

<ParamField query="--add-java-repository" type="boolean" default="false">
  Let `--java` add the Java vendor's package repository to the system package manager.
</ParamField>

<ParamField query="--mcdr-venv" type="boolean" default="false">
  Create an isolated MCDReforged environment under the server directory instead of using the global `mcdreforged` command.
</ParamField>

`--json` prints a machine-readable result, and `--no-interactive` produces append-only output for CI logs. See [Global Flags](/commands/global-flags).

See also [`lucy add`](/commands/add), [`lucy remove`](/commands/remove), and [`lucy file`](/commands/file).
