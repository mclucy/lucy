---
title: "Network cache and content storage"
description: "Request indexing, artifact verification, expiration, and distinct object-store lifecycles"
---

`cache` stores reusable network responses separately from a workspace. Its index maps a canonical request key to an entry with a content digest, filename, kind, integrity metadata, size, and expiration. The bytes live in a `cas.Store` addressed by SHA-256. Several request keys can refer to the same object; an object is reclaimed only when no retained index entry references it.

Metadata and artifacts have separate policy limits and lifetimes. The default metadata refresh period is four hours and the artifact retention period is seven days; request-specific metadata can choose a different TTL. Expiration affects whether an indexed response can be reused, not the meaning of a lock or receipt. Non-success HTTP responses are not stored as successful metadata responses.

## Publication and verification

A download is staged while its content digest and any supplied upstream integrity expectation are checked. Failed integrity checks do not publish the new destination or cache entry. On a cache hit, bytes are copied from the indexed object; installation then verifies the materialized artifact against the hashes recorded in the lock. A corrupt or unreadable cached object can be treated as a miss during an online download.

Installation also has workspace-local materialization under `.lucy/downloads`, organized by a hash of the artifact URL and its filename. It checks those bytes against the artifact hashes before reuse. If local materialization fails verification, the bad copy is discarded. In offline mode Lucy can use a suitable network-cache entry without fetching it, but still verifies the result; an absent or expired usable entry cannot supply the bytes.

## Separate stores

The global network cache and the workspace-local tracked-file store both use content-addressed storage but have different owners and retention rules. The network cache index represents reusable request results. `.lucy/objects/sha256/` contains captured working-file contents referenced by declarations, history, and pending transactions. Clearing network cache does not clear tracked-file history or workspace-local materialized downloads.

An object digest identifies content; it does not by itself assert upstream provenance. A verified lock hash ties expected bytes to an artifact record, while cache integrity metadata records what was checked when the response was acquired.
